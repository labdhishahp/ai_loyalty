# WHAT INSTALLS WHAT, as of @vercel/python@17.
#
# The builder installs from pyproject.toml (then uv.lock), NOT from this file.
# An earlier comment here claimed the opposite, which was true of the pinned
# 4.3.1 builder and is no longer. This file is what a developer installs from
# locally, and the two are kept identical by a test -- so the deployment is
# still covered either way, but the reason is worth stating correctly.
#
# EVERY runtime import of the API must appear here. Two did not, and the
# omission was invisible locally because the virtualenv had them from
# `pip install -e .`: `mcp` (api/app.py imports mcp_server, which imports the
# SDK at module scope) and `PyJWT` (core/auth.py:29). Neither arrives as a
# transitive dependency of anything below, so the function would have failed to
# import at all -- every route, including /api/health, returning 500.
# tests/test_deployment.py now asserts this file covers the import graph.
#
# UPPER BOUNDS ARE DELIBERATE. These are floors AND ceilings because this
# project has already lost a day to a major-version bump: the MCP SDK renamed
# FastMCP to MCPServer and switched to snake_case fields between 1.x and 2.x. A
# bare `>=` means a Vercel build months from now resolves a major it has never
# been tested against, and the failure appears at deploy time rather than here.
# Raise a ceiling deliberately, with the tests run against it.

psycopg[binary]>=3.2,<4
